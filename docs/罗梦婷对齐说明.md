# 气候证据链 Demo：罗梦婷对齐说明

版本：v0.1（初赛 Demo 基础框架）  
对齐目标：明确 AI 如何识别“承诺 / 行动 / 绩效”，以及如何按单条承诺判断 A/B/C 断点。

## 1. 项目边界

本项目处理上市公司可持续发展 / ESG 报告中与温室气体、碳排放、能耗、绿电直接相关的内容。

系统输出的是“文本证据链核查线索”，不判断企业是否漂绿、造假或违规，也不把“目标尚未完成”直接认定为负面结论。所有断点候选均需人工复核。

当前 Demo 阶段完成：

- PDF 上传、逐页文本抽取、基础页眉页脚清洗；
- 文本抽取调试台：页数、字符数、重复行剔除、分页原文、清洗文本、TXT 导出；
- 承诺 / 行动 / 绩效 / 断点四区页面；
- 本地规则分析预览，上传后自动生成三类要素与断点候选；
- 固定 AI 输出协议与演示数据结构。

暂未接入：真实大模型分类、跨报告自动归并、OCR。当前断点由规则生成，用于流程验证，正式结论仍需人工复核。

## 2. 三类要素的统一判定口径

### 2.1 一句话只打一个标签

标注单元为报告中的一个原句。AI 输出必须保留原文 `source_quote`、物理页码 `page` 和报告年份 `report_year`。不得改写原文作为证据。

若同一句同时包含目标、行动和结果，按以下优先级处理，并标记“待核”：

1. 有未来年份与量化目标：优先视为承诺；
2. 描述过去或当前已经实施的措施：行动；
3. 描述已经发生、带数值和单位的结果：绩效；
4. 仍无法确定：输出“存疑”，不强行归类。

### 2.2 有效气候承诺

必须同时满足以下三项：

1. 有明确量化指标；
2. 有确定的截止年份；
3. 与温室气体排放、碳排放强度、能耗、绿电占比、碳达峰或碳中和直接相关。

示例：

- “2030 年绿电采购占比提升至 40%”；
- “2028 年吨钢碳排放较 2020 年下降 18%”。

不属于有效承诺：

- “持续推进绿色低碳转型”；
- “积极落实双碳目标”；
- “力争早日实现碳中和”（没有量化指标和确定年份）。

注意：手册中“未来计划、意向按承诺处理”只说明它不属于行动；若该计划不满足量化和年份要求，也不能自动成为“有效气候承诺”，应不标注或标记存疑。

### 2.3 有效减排行动

判定重点是企业“已经做了什么”，不要求附带数字。

必须满足：

1. 描述已经落地实施的项目、技术改造、采购安排或管理措施；
2. 与气候目标、碳排放、能耗或绿电直接相关；
3. 不是单纯的未来计划、愿景或宏观宣传。

示例：

- 建设分布式光伏并网；
- 完成余热回收改造；
- 签订绿电采购协议；
- 上线碳台账或能源管理平台。

不属于行动：

- “计划建设光伏项目”；
- “未来将开展节能改造”；
- “深化绿色转型”。

### 2.4 量化绩效

必须同时满足：

1. 描述已经发生、当期或历史结果，而不是未来目标；
2. 有可量化数值和单位；
3. 与碳排放、能耗或绿电相关。

示例：

- 本年度 Scope 1+2 碳排放 18.2 万吨 CO₂e；
- 本期绿电采购占比 21%；
- 吨产品碳排放同比下降 6.3%。

不属于绩效：

- “减排效果显著”；
- “能耗水平持续提升”；
- “2030 年碳排放下降 30%”。

## 3. 承诺—行动—绩效如何匹配

每条承诺分配唯一编号 `C-01`、`C-02`……，行动与绩效必须填写对应承诺编号。不能把 A 承诺的绩效拿来补齐 B 承诺。

匹配需同时考虑：

| 维度 | 匹配要求 |
| --- | --- |
| 主题 | 碳排放、能耗、绿电、碳中和等指标属于同一主题 |
| 时间 | 行动发生在承诺发布之后；绩效发生在行动之后或对应报告期内 |
| 主体 | 同一企业、同一业务范围或可解释的组织边界 |
| 语义 | 行动或绩效与承诺中的指标、措施存在直接对应关系 |
| 粒度 | 判断 B 类断点时，集团汇总绩效不能替代单项行动绩效 |

匹配结果只表示“文本层面存在对应证据”，不代表绝对因果，也不代表目标已经完成。

## 4. A/B/C 断点判定

断点判定单位是一条承诺，不是整篇报告。系统应跨多年报告追踪同一企业、同一承诺，并为每条承诺独立维护证据链。

| 类型 | 触发条件 | 不触发 / 转交复核 |
| --- | --- | --- |
| A 有承诺，无跟进 | 承诺发布后的后续年度中没有对应行动，也没有对应绩效更新 | 只要检出对应行动或绩效，就不判 A；若存在绩效但无行动，转 C |
| B 有行动，无量化绩效 | 某项明确行动落地，但找不到该行动直接对应的减排量、节能量、发电量或绿电增量 | 仅披露集团总排放、总能耗等汇总结果，仍判 B |
| C 有绩效，无行动支撑 | 存在已发生的量化绩效，但全文找不到可支撑该结果的对应行动 | 相关行动只在另一条业务或另一承诺中找到时，不跨承诺混用，标存疑 |
| 完整链路 | 同一承诺下同时具有对应行动和对应量化绩效 | 只表示证据链完整，不表示承诺已达成 |

建议判定顺序：

1. 先识别并编号所有有效承诺；
2. 将行动和绩效按主题、时间、主体、语义匹配到承诺；
3. 对每条承诺检查是否有行动、是否有绩效；
4. 对无行动但存在绩效的记录生成 C 类候选；
5. 对有行动但无行动级绩效的记录生成 B 类候选；
6. 对承诺发布后所有后续年度均无行动、无绩效的记录生成 A 类候选；
7. 证据边界不清时输出“存疑”，不强行给出 A/B/C。

## 5. AI 固定输出协议

正式 Schema 见：

- `docs/ai-output.schema.json`
- `docs/ai-output.example.json`

每条要素至少包含：

- `content`：结构化描述；
- `element_type`：`commitment` / `action` / `performance`；
- `source_quote`：逐字原文；
- `report_year` + `page`：可追溯来源；
- `confidence`：模型置信度，仅用于复核排序；
- `review_status`：已核 / 待核 / 存疑。

承诺额外输出 `normalized_target`、关联行动、关联绩效和 `chain_status`；行动额外输出 `commitment_id`；绩效额外输出指标、数值、单位、行动编号和统计口径。

系统不得仅输出自然语言结论。前端、人工标注表和最终评测都应消费同一结构化结果。

## 6. 开发需求与验收标准

### P0：本次 Demo

- 上传 PDF，限制 30 MB，仅接受 PDF；
- 逐页提取文本，返回物理页码；
- 提供原始文本与清洗文本；
- 识别并展示页数、字符数、空页、重复页眉页脚；
- 无文本层时给出 OCR 风险提示；
- 四区数据由固定协议驱动，不把演示数据写成真实识别结果；
- 支持 TXT 下载，便于检查抽取质量。

### P1：下一步 AI 接入

- 按章节或重叠窗口切分文本，避免跨页语义断裂；
- 每条结果保留页码和原句；
- 三类要素分开抽取，再用规则进行承诺编号和链路匹配；
- 先输出候选，再进行断点判定；
- 对低置信度、跨报告匹配、汇总绩效替代单项绩效等情况标记“待核”。

### P2：评测与迭代

- 以人工标注表九列字段作为金标准；
- 分类指标至少统计承诺 / 行动 / 绩效的精确率、召回率；
- 断点指标分 A/B/C 分别统计；
- 同时评估“原文可追溯率”和“页码正确率”；
- 每条人工复核结果回写复核状态，形成下一轮 Prompt 和关键词库迭代依据。

## 7. 需要和罗梦婷确认的四个问题

1. 断点 A 的观察窗口：是否要求承诺发布后连续两个完整年度均无行动与绩效，还是只要最新报告仍无跟进即可标记？
2. 汇总绩效边界：哪些“集团整体绩效”可以被视为与承诺有关？本 Spec 暂按“可关联到承诺，但不能替代单项行动绩效”处理。
3. 跨年度编号：企业首次出现承诺时生成 `C-xx` 后，后续报告是否沿用同一编号，还是每年重新编号后再由系统做实体归并？
4. 存疑阈值：AI 置信度、语义匹配和人工复核如何分工？本 Spec 暂不把置信度作为自动定性的依据。

以上四项一经确认，应写入下一版标注手册和 Prompt 版本说明，不通过 Prompt 临时改变口径。
