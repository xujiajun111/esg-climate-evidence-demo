# AI 语义复核接入说明

版本：v0.8  
更新日期：2026-11-25

## 1. 定位

当前 Demo 的分析流程是“规则候选 + 可选 AI 语义复核”：

1. PDF 在浏览器本地完成文本抽取、清洗和规则分类；
2. 规则引擎建立承诺、行动、绩效及 A/B/C 断点候选；
3. 如果配置了 AI 接口，系统把候选 ID、类型、原文片段、年份和页码发送给模型；
4. 模型返回“确认 / 存疑 / 排除”、置信度和简短理由；
5. UI 同时展示规则匹配度与 AI 建议，最终结论仍由人工复核。

这种设计保证：

- 没有 API Key 时公网 Demo 仍可完整运行；
- AI 只处理结构化的候选，不需要每次把完整 PDF 发送给模型；
- AI 输出可追溯、可回退，不直接生成企业负面结论；
- 规则回归测试继续负责防止基础分类退化。

## 2. OpenAI 兼容接口

在页面右上角打开“分析设置”，填写：

- **接口地址**：完整的 Chat Completions 地址，例如
  `https://api.example.com/v1/chat/completions`；
- **模型名称**：接口支持的模型 ID；
- **API Key**：可选。使用自建代理或本地模型时可以不填。

浏览器会发送：

```json
{
  "model": "your-model",
  "temperature": 0,
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "候选 JSON" }
  ]
}
```

模型应返回：

```json
{
  "reviews": [
    {
      "id": "A-01",
      "suggestion": "确认",
      "confidence": 0.9,
      "rationale": "描述的是已经完成并网的项目"
    }
  ]
}
```

## 3. CORS 与会话安全

静态 GitHub Pages 无法隐藏长期 API Key，因此当前实现属于 BYOK
（Bring Your Own Key）演示方式：

- Key 只写入当前标签页的 `sessionStorage`；
- 关闭标签页后不会继续保留；
- 如果模型服务不允许浏览器跨域请求，请改用同源代理；
- 不要在公开仓库、截图或演示视频中暴露真实 Key。

正式比赛环境建议部署一个轻量代理：

```text
GitHub Pages 前端
        ↓ 同源或受控跨域请求
云函数 / Worker / Node 服务
        ↓ 服务端环境变量保存 API Key
大模型服务
```

代理端还应增加请求频率限制、输入长度限制和日志脱敏。

## 4. 失败与回退

以下任意情况都会自动回退到规则结果：

- 未配置接口地址或模型；
- 网络超时；
- 浏览器 CORS 校验失败；
- 接口返回非 2xx；
- 返回内容不是合法 JSON；
- 返回 ID 不在当前候选集合中。

回退不会删除规则抽取文本、原文页码或人工复核操作。

## 5. 评测建议

AI 模式正式对外前，至少增加以下对照：

| 指标 | 规则基线 | 规则 + AI |
| --- | ---: | ---: |
| 承诺 Precision / Recall / F1 | 待标注 | 待标注 |
| 行动 Precision / Recall / F1 | 待标注 | 待标注 |
| 绩效 Precision / Recall / F1 | 待标注 | 待标注 |
| A/B/C 断点精确率与召回率 | 待标注 | 待标注 |
| 原文与页码可追溯率 | 100% | 100% |
| 单个请求的 Token 与延迟 | 不适用 | 待测量 |

在尚未完成双人标注金标准前，不应把模型自报置信度解释为真实准确率。
